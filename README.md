# maki-freeflow

Maki providers backed by the [pi-freeflow](https://github.com/trefeon/pi-freeflow)
daemon (v1.34.0, MIT © trefeon), vendored verbatim under `vendor/`. See
[LICENSE](./LICENSE). Requires Node 22.19+ or Bun. The daemon starts on demand at `127.0.0.1:28180`.

## Setup

Add this to your global Maki `init.lua`:

```lua
maki.pack.add({
  "https://github.com/MrBanh/maki-freeflow",
})
```

Restart Maki and approve the package permissions. Requires Node 22.19+
or Bun, plus npm on PATH for automatic dependency installation. On first
startup the plugin installs the pinned `undici` dependency into the loaded
checkout's `vendor/` directory. Each new package revision is set up separately;
existing installations do not run npm again. The checkout must be writable.

Check readiness with `/freeflow status`, then select a FreeFlow model.
Deploying a relay is optional; without one, requests go directly upstream.

If automatic setup fails, the notification includes the error and the actual
vendor directory. Install manually in **that directory** (not a separate
development clone), then run `/freeflow status`:

```
cd vendor && npm ci --omit=dev
```

## Deploy your own relay

```
/freeflow deploy
/freeflow deploy cloudflare
/freeflow deploy cf my-relay
/freeflow deploy deno
/freeflow deploy vercel
```

With no platform, a picker opens. The command asks for a masked API token
and a project name (generated by default). Tokens come from:

- **Cloudflare:** API Tokens with Account Read and Workers Scripts Edit.
- **Deno Deploy:** an organization access token.
- **Vercel:** a personal access token.

Deployment uses the upstream API clients and worker templates, including
platform name normalization, build polling, failure cleanup, upstream
allowlisting, request guards, streaming, and a fresh shared secret.
Progress appears in a window. The deployed relay is saved and activated in
the shared pool, then probed with its secret (with retries for edge routing).
A failed probe keeps the deployment registered so it can be retried:

```
/freeflow test my-relay
/freeflow test 1
/freeflow test opencode
/freeflow test 1 --chat
/freeflow list
/freeflow use 1
/freeflow label 1 cf-sg
```

The default probe requests the model catalog; `--chat` performs a minimal
inference request. Redeploying an existing URL rotates its secret and
preserves a custom label. Pool changes are picked up by the running daemon.
Deployment preserves the pool mode; use `/freeflow auto` if it was off.

Platform tokens stay in memory and the deploy child's environment; they are
never put in command arguments, chat history, temporary files, or job output.
Relay shared secrets are stored in `pi-freeflow-relay-state.json` under
`PI_FREEFLOW_DATA_DIR` (default `~/.pi/agent`). Exports strip those secrets
unless `/freeflow export [path] --include-secrets` is requested.

Other commands: `status`, `models`, `auto`, `spread`, `on`, `off`,
`add <URL> [name]`, `url [URL]`, `remove <target>`, `kill`, `refresh`,
`debug on|off`, `export [path] [--include-secrets]`, `import <path> --replace`.
The command layer still reports unsupported host-specific upstream commands
(Cline login, startup installation, widget controls, and vendor updates).

## Verification

```
node --experimental-strip-types --test test/deploy.test.mjs
lua test/deploy.lua
lua test/setup.lua
node --test test/setup.test.mjs
```

Tests mock platform APIs and use an isolated state directory; no cloud
resources or live upstream inference requests are created.
